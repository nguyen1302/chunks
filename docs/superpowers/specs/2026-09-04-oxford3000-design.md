# Chunks — Oxford 3000 Study Plan — Design

**Date:** 2026-09-04
**Status:** Approved for build
**Base:** existing chunks app (MongoDB via lib/store, SRS in lib/schedule, review
modes Write/Cloze/Reverse, TTS, tags, reminders, stats).

## Goal

Learn the Oxford 3000 (American English) the smart way: introduce words a few
per day (drip), each with Vietnamese meaning + example + collocation (context),
then learn them through the app's existing spaced-repetition + active-recall
loop. Avoid dumping 3000 words at once.

## Data

- **Parsed list** `data/oxford3000.json`: `[{ word, pos, level }]` (2996 words;
  A1 896 · A2 800 · B1 700 · B2 600), sorted by level then alphabetically.
- **Enriched** `data/oxford3000-enriched.json`: `{ [word]: { meaning_vi,
  example, collocation } }` generated once via `scripts/enrich-oxford.mjs`
  (batches through the local `claude` CLI — no API key).
- **Mongo `wordbank`** collection: `{ word, pos, level, meaning_vi, example,
  collocation, source:"oxford3000", status:"dormant"|"active", order }`.
  `order` = global A1→B2 index for deterministic drip. Index on `{status, order}`.
- **Mongo `studyPlan`** (single doc `{ _id:"plan" }`): `{ enabled, newPerDay,
  startLevel, lastActivatedDate }`.

## Integration — reuse everything

**Activation converts a wordbank entry into a normal Expression** so it flows
through the existing review/stats/tags/TTS machinery with zero new review code:

- On activation, create an Expression: `text=word`, `meaning=meaning_vi`,
  `example=example`, `source="Oxford 3000 · <LEVEL>"`, `tags=[<level lc>,
  "oxford3000"]`, `synonyms=[]`, new-expression schedule (`reviewDue=today`,
  level 0). The **collocation** is added as one backfilled review example
  (result null) so it shows under "past sentences".
- Mark the wordbank entry `status:"active"` (so it is never re-activated).

**Drip scheduler** — `/api/study/tick` (GET), called by the client on app load:
- If `plan.enabled` and `plan.lastActivatedDate < today`: activate the next
  `newPerDay` dormant words (ordered by `order`, i.e. A1 first), then set
  `lastActivatedDate=today`. Idempotent per day. Returns `{ activated }`.
- `startLevel`: only words at or above the chosen level are eligible (A1 default
  → all; B1 → skip A1/A2).

**Study plan settings + progress** — on the Progress page:
- A "Study plan" card: enable toggle, words/day (5–30), start level; saved via
  `PUT /api/study/plan`.
- A per-level progress row: for `oxford3000`-tagged expressions, show
  `activated` and `mastered` (level ≥ 3) counts per CEFR band, e.g.
  "A1 · 36 learning · 4 solid / 896".

## API

- `GET  /api/study/tick` — run today's drip; returns `{ activated }`.
- `GET  /api/study/plan` — current plan + progress summary.
- `PUT  /api/study/plan` — update `{ enabled, newPerDay, startLevel }`.

## Import

`scripts/import-oxford.mjs` — reads `oxford3000.json` + `oxford3000-enriched.json`,
upserts `wordbank` docs (dormant, with `order`). Re-runnable (upsert by word).
Does not touch existing expressions.

## Testing

- Unit: `lib/study.ts` pure helpers — `nextBatch(dormant, plan, today)` picks the
  right words (respects startLevel, newPerDay, once-per-day).
- Live: import a few, run tick → correct number of Expressions created + tagged;
  re-tick same day → no duplicates; Progress shows per-level counts.

## Sequencing

1. Enrich (running) → 2. import wordbank → 3. lib/study + API + tick → 4. UI
(study plan + progress) → 5. live verify → push. Reuses SRS/modes/TTS/reminders.

## Risks

- Enrichment quality varies per word (acceptable; editable later in Library).
- Drip depends on the client hitting `/api/study/tick`; a missed day just delays
  new words (reviews still work). Could later move to the daily cron.
